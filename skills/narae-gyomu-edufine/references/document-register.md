# 에듀파인 문서등록대장 검색과 기안자별 문서 목록

## 범위와 검증 상태

2026-10-15 충북 K-에듀파인 업무관리에서 **문서관리 → 문서함 → 문서등록대장**과 검색·문서정보 조회를 실기 확인했다. 상단 문서관리 메뉴를 열면 문서함 아래 문서등록대장이 보인다. 화면 제목과 메뉴경로가 문서관리 > 문서함 > 문서등록대장인지 확인한다. 권한·기관에 따라 메뉴가 달라질 수 있으므로 현재 화면으로 재확인한다.

## 검색 기준

1. 상대 기간을 사용자 시간대의 날짜로 확정한다. 2026-10-15에 받은 “작년”은 **2025-01-01~2025-12-31**이다. “작년”을 2025학년도나 최근 365일로 바꾸지 않는다. 화면이 연도와 날짜를 따로 요구하면 둘 다 2025년으로 맞춘다.
2. 문서의 주제·제목 조건과 **기안자** 조건을 구분한다. 발신자·등록자·처리자·담당자 이름을 기안자로 간주하지 않는다. 제목만으로 내용이나 기안자를 추정하지 않는다.
3. 실제 보이는 검색 필드에 제목과 기안자를 지정한다. 기안자 검색 필드가 없으면 주제 결과를 연 뒤 문서 정보/결재경로의 실제 기안자를 대조한다. 검색 실패나 접근 제한을 결과 0건으로 기록하지 않는다.

## 브라우저 절차

1. 업무포털의 **K-에듀파인** 링크로 이동하고 업무관리 영역에서 **문서관리 → 문서함 → 문서등록대장**을 연다. 초기 로딩 중 DOM이 비어 있을 수 있다. 흰 화면을 즉시 로그인 실패로 단정하지 말고 현재 로딩과 페이지 상태를 확인한다.
2. 등록대장은 주 화면 내부의 별도 **iframe**이다. 현재 DOM에서 그 프레임의 실제 id를 확인해 frameLocator로 접근한다. 이번 환경에서 메뉴 아이디는 `A00AAB0107001`이었고 프레임 id에 이 값과 실행마다 달라지는 숫자가 들어갔다. 실행 시 숫자나 전체 프레임 id를 고정하지 않는다.
3. 기본 검색의 **제목**, **등록일자시작**, **등록일자종료**를 사용한다. **등록일자 단위 년 선택**에서 대상 연도를 고르면 해당 연도 1월 1일~12월 31일로 날짜가 반영됐다. 검색 뒤 연도 선택 표시가 ‘년도’로 돌아갈 수 있으므로 실제 두 날짜 값을 대조한다. 이번 시험의 날짜 기준은 **등록일자**다.
4. **조회옵션펼치기**를 열고 **기안(접수)자**에 대상 이름을 입력한다. 별도의 결재(담당)자와 혼동하지 않는다. 문서종류 선택은 전자/비전자 구분이므로 기안문서 여부의 필터로 사용하지 않는다. 제목과 날짜·기안(접수)자를 확인한 뒤 프레임 안의 **조회**를 누른다.
5. 조회 직후 이전 목록이 잠시 남을 수 있다. 결과 갱신을 확인하고 목록의 등록일·기안(접수)자가 현재 조건과 맞는지 대조한다. 정확한 제목어를 먼저 검색하고 관련 문서가 누락될 수 있으면 적절한 상위어로 보완한다. 이번 시험은 `개별화교육계획`에서 5건, `개별화`에서 관련 평가 1건을 더해 6건이었다. 보완 조건과 포함 이유를 결과에 기록한다.
6. **총 N건 / 조회 M건**, **페이지당 건수**, 페이지 링크를 확인한다. 전체 페이지를 확인하고 문서번호로 중복을 제거한다. 이번 시험은 총 6건/조회 6건으로 1페이지 전체였다. 많은 결과는 현재 페이지의 확인 범위를 기록하며 다음 페이지로 이어간다.
7. 목록의 **기안/접수** 이름, **기안문서** 상태 아이콘, 내부결재 여부를 함께 대조한다. 수신문서의 접수자를 기안자로 기록하지 않는다. 문서를 한 건 선택하고 상단 **문서정보**를 연다. 이번 화면의 체크박스 input은 0 크기이고 같은 셀의 label이 클릭용이었다. check/click이 실패하면 실제 checked 값과 DOM을 확인한 뒤 해당 label을 클릭한다. 입력값을 직접 변경하거나 같은 동작을 반복하지 않는다.
8. 문서정보는 결과 아래 **apprInfoWnd iframe → docInfoFrame iframe**의 인라인 영역에 표시됐다. 기본 **결재경로** 탭에서 ‘기안’ 처리자를 확인할 수 있다. 안쪽 **문서정보** 링크를 선택하면 정식 문서번호·기안일시·시행종류 등이 나온다. 제목이 현재 선택한 문서와 일치한 뒤 읽고, 목록 등록일자와 문서정보 기안일시를 별도 항목으로 보존한다. 다른 행으로 바꾸면 선택을 한 건만 유지하고 상단 문서정보를 다시 조회한다.
9. 본문 확인은 목록의 **문서 제목**을 클릭해 WXS를 연 뒤 [wxs-cli.md](wxs-cli.md)의 CLI로 조회한다. 문서정보 인라인 영역 열기와 WXS 본문 열기를 구분한다. 최초 기기 앱·서비스 접근 팝업은 업무포털 공통 지침의 사용자 직접 허용 절차를 따른다. 공람확인·접수·결재 등 별도 처리 버튼은 누르지 않는다.

## 결과 형식

목록에는 **제목, 문서번호, 등록일/생산일과 날짜 기준, 실제 기안자, 상태, 확인 근거**를 넣는다. 문서번호가 없거나 볼 수 없는 항목은 미확인으로 표시한다. 본문을 실제 읽었을 때만 요약을 덧붙인다. 등록대장 목록 메타데이터와 WXS 본문 확인을 구분한다.

기록할 검색 요약: 검색 기간, 날짜 기준, 제목어, 기안자, 후보 수, 확정 수, 확인한 페이지/전체 페이지, 접근 제한·본문 미확인 건수. 화면에 전체 건수가 없으면 확인한 건수만 보고한다. 학생 이름·장애·의료 등 요청 목록에 불필요한 민감정보는 추출하지 않는다. 실제 문서 목록과 본문은 공개 스킬·예제·옵시디언의 배포 자료에 넣지 않고, 요청한 개인 결과물에만 정리한다.

## 현재 시험 목표

2026-10-15: 2025년 등록일자 전체와 사용자 지정 기안자로 검색해 관련 6건을 확인했다. 정확한 제목어 결과 5건과 보완 검색의 관련 평가 1건을 구분했고, 6건 모두 기안문서·기안자·정식 문서번호·기안일시를 대조했다. 대표 계획 문서의 기안 처리자와 WXS 본문도 확인했다. 실제 목록은 개인 결과물로 정리하며 배포 스킬에 문서 제목·학생 정보·문서 원문을 복사하지 않는다. 다른 기간·기관과 다수 페이지 이동은 이번 시험에서 실행하지 않았다.
