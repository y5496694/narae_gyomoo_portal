# 진행 문서와 공람 조회

로그인은 [공통 절차](../../narae-gyomu-work-portal/references/login.md)를 따른다. 공람은 날짜 지정이 없으면 **최근 한 달부터 오늘까지**로 조회한다. 실제 시작일·종료일을 보고한다. 예를 들어 10월 16일이면 9월 16일~10월 16일이다. 무기한 전체 공람을 기본으로 조회하지 않는다.

## 실제 확인한 메뉴

| 목적 | 메뉴 경로 | 확인한 iframe 경로 |
| --- | --- | --- |
| 진행 중인 기안·결재 문서 | 문서관리 → 결재 → 문서진행 | `/bms/cz/cb/viw/retrieveSanctnProgrsDocList.do` |
| 담당 확인 대기 | 문서관리 → 접수함 → 업무담당확인 | `/bms/cz/cb/viw/retrieveJobChrgCnfirmDocList.do` |
| 아직 상신하지 않은 초안 | 문서관리 → 기안 → 임시저장 | `/bms/cz/cb/viw/retrieveTmprCstdyDocList.do` |
| 나에게 도착한 공람 | 문서관리 → 공람 → 공람대기 | `/bms/cz/cb/viw/retrieveCnrsWaitDocList.do` |
| 이미 완료한 공람 | 문서관리 → 공람 → 공람완료 | `/bms/cz/cb/viw/retrieveCnrsComptDocList.do` |

메뉴 이름·현재 사용자·소속을 실제 화면에서 확인한다. 위 경로를 원본 문서 열기 URL이나 업무 API로 재생하지 않는다. Nexacro 안의 목록 iframe이 비어 있으면 **현재 화면에서 관찰한 그 iframe의 실제 src**를 같은 인증 세션의 브라우저 탭으로 열고 메뉴명·조회 조건을 대조할 수 있다. 과거 세션 값·개인 ID·추측한 URL은 쓰지 않는다.

## 조회와 범위 확인

공람대기와 공람완료에서 `등록일자`를 같은 기간으로 설정하고 조회한다. 페이지당 건수를 바꾸면 날짜가 기본값으로 돌아갈 수 있으므로 **건수 설정 → 날짜 입력 → 조회 → 현재 표시값 확인** 순서로 한다. 날짜를 비워도 서버가 최근 한 달로 복원할 수 있다. 입력란을 비운 것만으로 전체 기간을 조회했다고 말하지 않는다.

총 건수·현재 페이지·조회한 행 수를 기록하고 마지막 페이지까지 수집한다. 문서번호·제목·발송기관·공람지정자·기안일시·공람도착일시를 구분한다. 공람완료에는 공람일시도 기록한다. 대기/완료 중복은 문서번호로 대조한다. 두 목록 모두 0건일 수 있다.

진행 문서를 전부 확인해 달라는 요청에는 문서진행·업무담당확인·임시저장을 확인한다. 진행 목록의 기본 한 달이 0건이어도 전체 기간에 진행 문서가 없다고 단정하지 않는다. 가능한 조회 기간을 명시적으로 넓혀 다시 확인하고 실제 범위를 보고한다. 임시저장은 제목·저장일·첨부 표시를 별도로 기록한다. 오래된 잔여 초안이 있을 수 있으므로 최종 제출 문서와 대조하기 전에는 미제출 업무로 확정하거나 삭제하지 않는다. 읽기 전용 공문용 자동 닫기를 편집 가능한 초안에 적용하지 않는다. 결재대기·발송대기 등 다른 상태는 요청 범위와 현재 메뉴를 확인해 추가 조회한다.

## 본문과 첨부 읽기

목록 정리 후 [WXS 연결](wxs-cli.md)을 따른다. 여러 제목을 연속 클릭해 WXS 창을 쌓지 않는다. 같은 팩의 `read-next --background --attachments-dir ...`를 먼저 대기시키고 `ready:true`를 확인한 뒤 웹에서 **한 건**의 제목을 누른다. 본문·모든 첨부 파일을 확보하고 `closed:true`를 확인해야 다음 제목을 연다. 저장한 첨부의 내용 검토는 WXS를 닫은 뒤 진행할 수 있으며 보고를 완성하기 전에 모두 대조한다.

읽기 전용 비전자 공문은 편집기 본문 대신 첨부 PDF 등에 원문이 있을 수 있다. 빈 편집기만 확인한 상태를 본문 읽기 완료로 처리하지 말고 그 원문 파일을 실제로 읽는다. 본문 속 날짜·대상·기한·제출 방법을 첨부 계획·서식과 대조하고 수정 공문이 있으면 변경 전후를 구분한다.

공람확인·일괄처리·공람의견등록·삭제는 조회와 다른 동작이다. 내용 정리 요청만으로 이 버튼을 누르지 않는다. 시스템의 열람 이력은 남을 수 있다.

**보안문서의 추가 인증은 별도 상태다.** WXS 인증서 창이 특정 공문을 열면서 나오면 사용자에게 해당 문서의 보안 인증이 필요하다고 알린다. 그 WXS와 인증창은 그대로 보존하고 해당 문서는 본문 미확인·인증 대기로 기록한 뒤 다음 문서로 넘어간다. 이 경우 대기 창을 남기는 것은 순차 열람 원칙의 예외다. 기존 대기 창을 새 문서의 창으로 오인하지 않는다. 사용자 인증 완료 뒤 실제 제목·창을 다시 대조해 읽기를 재개한다. 다른 문서도 열리지 않고 실제 세션 만료가 확인되는 경우에는 [공통 로그인·30분 세션 유지](../../narae-gyomu-work-portal/references/login.md)를 따른다.

보고에는 확인한 본문 수, 첨부 수와 형식, 실패·암호화·보호 때문에 읽지 못한 파일, 대기/완료 상태와 조회 기간을 명시한다. 학생 주소·연락처·식별번호·장애 정보, 제품번호·인증 정보는 업무 요약에 불필요하게 재수록하지 않는다.
