# 재기안 후 중복 회수본 정리

사용자가 대체 기안과 기존 회수본 정리를 맡긴 경우 수행한다. 이번 삭제를 직접 하겠다고 하면 에이전트는 중단한다. 정리 요청이 없거나 새 기안의 결과가 불명확하면 삭제하지 않는다. 발송·강제 반송·권한 조작으로 확대하지 않는다.

1. 대체 기안의 제목·기안자·새 기안 시각·현재 결재자와 서버의 본문·첨부를 확인한다. 첨부 오류를 고친 건은 [원본/서버 해시와 열기 검증](../../wxs-cli/references/attachment-integrity.md)을 마친다.
2. 최신 문서진행 목록에서 같은 제목의 **이전 기안 시각 + 회수**인 행만 선택한다. 새 진행 문서와 다른 업무는 선택 해제되어 있어야 한다. 제목만으로 같은 문서를 판단하지 않는다.
3. 실제 `삭제 / 연계반송`을 한 번 실행한다. confirm의 현재 ID와 원문을 대조해 처리한다. `tabs`에서 후속 의견작성 창을 찾아 제목·삭제 모드·대상을 확인하고 중복 회수본 정리 사유를 입력한다. 현재 확인 버튼과 성공 안내도 한 번씩 처리한다.
4. 원래 목록을 실제 조회하여 **예전 회수 행 부재 + 새 진행 행 유지 + 다른 업무 유지**를 대조한다. 성공 alert와 닫힌 팝업만으로 완료라고 보고하지 않는다. 안내와 목록이 다르면 미확인으로 남기고 변경을 반복하기 전에 선택·대상 식별값·후속 창·세션을 확인한다.

확인창·프레임·부모 링크와 자식 span의 이벤트는 나래 브라우저의 `docs/dialogs-and-portal.md`를 따른다. 화면 전환으로 `navigationObserved:true`가 반환되면 클릭을 반복하지 않고 새 snapshot으로 결과를 읽는다. `inspect REF`는 현재 요소 속성과 선택한 form의 제한된 필드값을 읽는 진단이다. 업무 함수를 실행하거나 숨김 필드를 임의로 만들지 않는다. 일반 UI로 확인되지 않은 강제 삭제 함수를 실행하지 않는다.

실제 문서 ID·학생 정보·세션 주소·삭제 결과는 공개 문서와 Git에 저장하지 않는다.
