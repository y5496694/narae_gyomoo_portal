# 구조와 검증 기록

WXS (공문서 에디터, 프로그램 이름: WXS Client)는 에듀파인에서 공문을 열 때 실행되는 Windows MFC 프로그램이다. 이 `wxs-cli`는 제조사 공식 CLI가 아니라 이번 연구에서 만든 로컬 어댑터다. 이미 열린 MSHTML 문서·HwpCtrl의 COM 인터페이스를 사용한다.

연구 대상은 WXSClient.exe 3.0.0.2, x86 PE32, 235,928바이트였다. SHA-256: `78de1fd75cb5c0b1d59540d603e8fd83bd5078e65f423d4927b4ec614b01d56b`. 다른 버전·교육청의 동일 동작은 보장하지 않는다.

[REA](https://github.com/morluto/rea) 6.5.0과 Rizin 0.9.1로 실행 파일의 구조·리소스·문자열·시작 프로토콜을 조사했다. REA는 연구용 분석 도구이며 일반 사용에는 REA·Rizin·Ghidra가 필요하지 않다. WXS 실행 파일과 제3자 분석 런타임도 동봉하지 않는다.

```text
웹에서 공문/양식 열기 → 설치된 WXS Client
  → 실제 hwnd·pid 확인
  → WM_HTML_GETOBJECT → MSHTML COM
      ├─ HwpCtrl: GetTextFile / GetFieldText / PutFieldText
      ├─ DOM: 제목·비공개 사유·현재 입력값
      ├─ 기존 함수와 Nexacro 데이터셋: 과제·경로·수신자·관인 설정
      └─ HSAttach: 파일 추가 및 앱의 검증/업로드
```

`wxs_cli.py`는 진입점, `wxs_config.py`는 오프라인 검증, `wxs_native.py`는 창·COM 조회, `wxs_read.py`는 작업 소유 읽기 전용 문서의 순차 본문·첨부 저장과 닫기, `wxs_runtime.py`와 `wxs_actions.js`는 제한된 앱 동작이다. 임의 JS 실행이나 직접 서버 API 재생 명령은 노출하지 않는다. 발견한 `wxsclient://` 프로토콜의 세션 URL을 수집·재생하지 않는다. 임시저장은 기존 앱 함수를 통하며 상신을 호출하지 않는다.

저장된 첨부는 [형식별 읽기 도구](attachments.md)의 `attachment_reader.py`로 읽는다. HWP/HWPX는 나래 한글 오피스 CLI를 별도 프로세스로 실행한다. 나머지 형식도 원본 해시를 전후 대조하고 추출 성공과 내용 검토를 구분한다. 창 생성 시 인증서를 요구하는 보안문서는 읽기·닫기 대상에서 보류하고 그대로 보존한다.

## 검증 구분 — 2026-10-15

| 대상 | 확인 | 한계 |
| --- | --- | --- |
| 실제 공문 조회 | 2쪽 공문 1,434자 추출, 첨부 메타데이터, 추출 전후 수정 상태 동일 | 첨부 내용·그림·관인·레이아웃 제외 |
| 실제 개별 CLI 쓰기 절차 | 제목·본문·비공개 6호·과제·결재자 1명·수신자 1곳·PDF 첨부·기본 관인 자동발송 설정·임시저장 성공 | 충북 해당 세션의 연구 스크립트로 확인, 상신하지 않음 |
| 범용 배포본 조회 | 실제 열린 공문에서 inspect·text·attachments·draft-status 성공, 724자 추출, 편집 상태 동일, 프레임 오류 0 | 첨부는 DOM 표 조회이며 파일 내용은 읽지 않음 |
| 범용 배포본 쓰기 | 설정/계획·대상 일치·후보 중복·제한된 고정 액션·임시저장 메시지의 오프라인 모의 시험 | 배포본 전체의 실제 서버 저장은 재검증하지 않음 |

실제 공문·개인 ID·인증서·세션 토큰·원본 열기 URL·첨부 원본은 패키지에 포함하지 않는다. 사용자 설정과 실행 출력에는 업무 내용이 들어갈 수 있다. 배포본의 시험 결과는 [원본 팩 검증 기록](../../../docs/wxs-validation.txt)를 참조한다.

## 0.3.0 읽기 검증 — 2026-10-16

- 실제 충북 공람 화면에서 제목별 한 건씩 본문 추출, 앱 `Attach.saveFilesAs` 첨부 저장, 읽기 전용 상태 대조 후 닫기를 확인했다. 비전자 PDF 원문과 별도 보안 인증 요구 문서도 구분했다.
- `--background`는 제목 확인 후 해당 창만 숨긴다. 최초 활성화는 WXS 동작이므로 화면 점유를 완전히 방지하지 못한다. 실패한 일반 창은 활성화 없이 복원하며 보안 인증창은 닫지 않는다.
- 실제 HWP·HWPX·PDF·XLSX·XLS·이미지 첨부 읽기와 한국어 OCR, 큰 JPEG의 디코더 축소를 확인했다. 앱 저장이 실패한 파일은 미확인으로 남겼다.
- 합성 파일 시험은 나래한글 HWP/HWPX, PDF 텍스트/이미지, 암호 필요 PDF 거부, 숨은 엑셀 시트와 수식, DOCX 머리말·꼬리말·표, PPTX 슬라이드·노트, GIF 모든 프레임, 원본 보존을 포함한다. DOCX·PPTX는 합성 파일 시험 범위다.
- 창 제목/PID 변경, 쓰기 모드·수정 상태·프레임 누락, 중복 창, 신규 및 기존 보안 인증창 보존은 모의 시험으로 검증한다. 다른 기관·WXS 버전은 추가 검증 대상이다.

## 0.4.0 본문·캡처 검증 — 2026-10-29

- `wxs_document.py`는 빈 본문에 검토한 HWP를 끼우고 표준 필드와 전체 문서 원문을 대조한다. `GetFieldText(본문)`이 표 셀 원문을 포함하지 않는 실제 동작을 확인해 전체 `GetTextFile(TEXT)`를 검증에 사용한다.
- 실제 충북 WXS 새 내부결재 양식에서 제목·안내 문장·5열 표 삽입, 1쪽 배치, 서버 임시저장 성공 메시지, 저장 후 실제 한글 컨트롤의 150 DPI 전체 쪽 PNG 렌더링을 확인했다. 최초 삽입은 본문 필드만의 원문 검사에서 실패를 보고했으나 실제 전체 원문과 이미지를 대조해 삽입이 완료된 것을 확인한 뒤 재삽입 없이 저장했다. 전체 원문 검증의 수정된 분기는 모의 시험으로 확인했다.
- 새 기능 모의 시험은 입력 파일 변경, 기존 본문 보존, 제목 불일치, 원문 불일치, 캡처 중 문서 변경, 모든 쪽 생성, 기존 출력 보존을 포함한다. 다른 기관·WXS 버전·복잡한 문서의 조판은 추가 검증 대상이다.
- 캡처는 UI 화면 전체가 아닌 선택한 WXS `editor1` 페이지 렌더링이며, 서버 저장이나 상신의 증거로 단독 사용하지 않는다. 실제 원문·이미지·개인정보는 공개 저장소에 넣지 않는다.
