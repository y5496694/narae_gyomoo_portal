# 초안 설정

UTF-8 JSON을 사용한다. 상대 경로는 설정 파일 폴더 기준이며 BOM도 허용한다.

```json
{
  "expected_title": "",
  "title": "테스트",
  "body": "1. 관련: 테스트-1234(1234.1234..1)\n2. 테스트를 하고자 합니다.\n\n붙임  테스트 문서 1부.  끝.",
  "task_card": "실제 과제카드 명칭",
  "private_reasons": [6],
  "approver": {"name": "실제 결재자 이름"},
  "recipient": {"search": "부서 검색어", "name": "교육청과 부서를 포함한 실제 전체 명칭"},
  "auto_send": true,
  "attachments": ["C:\\사용자가 지정한 폴더\\첨부.pdf"],
  "save_name": "테스트"
}
```

| 항목 | 의미 |
| --- | --- |
| expected_title | 변경 전 현재 제목. 새 양식이면 빈 문자열. 필수 |
| title | 입력할 제목. 필수 |
| body / body_file | 본문 문자열 또는 UTF-8 텍스트 파일, 둘 중 하나. CRLF로 줄바꿈 변환 |
| body_hwp | 표·서식이 포함된 본문용 HWP. `{"path":"본문.hwp","expected_text":"전체 본문과 표 셀 원문"}`. body/body_file과 함께 사용 불가 |
| task_card | 실제 후보의 정확한 과제카드 명칭 |
| private_reasons | 비공개 선택과 사유 1~8호. `[6]`이면 6호만 선택 |
| disclosure | `{"mode":"partial","reasons":[6]}`처럼 공개 구분과 사유를 명시. mode는 public/partial/private. 공개는 빈 사유, 부분공개·비공개는 사유 필수. private_reasons와 함께 사용 불가 |
| approver | 현재 조직의 결재자 1명. 이름 중복이면 실제 확인한 id도 지정 |
| approval_route | `[{"name":"실제 검토자","id":"실제 후보 ID","role":"검토"},{"name":"실제 결재자","id":"실제 후보 ID","role":"결재"}]`. 기안자 다음 순서, 마지막 1명만 결재. approver와 함께 사용 불가 |
| recipient.search / name | 기관 검색어 / 검색 결과 전체 표시명과 정확히 일치하는 명칭 |
| auto_send | true만 지원. 대외 시행·발신명의 선택·기본 관인 1개 필요 |
| attachments | 실제 파일 경로 목록. 파일명·크기는 파일에서 산출 |
| save_name | 있으면 마지막에 서버 임시저장, 없으면 열린 양식에 입력만 함 |

선택 항목 생략은 해당 항목 유지다. `attachments: []`는 기존 파일을 지우지 않는다. 공개 구분·사유는 사용자 지시나 확인한 해당 업무의 기존 문서 기준으로 설정하고 임의로 정하지 않는다. 자동발송 해제·기존 경로/수신자/첨부 교체는 지원하지 않는다.

현재 지원은 **기안자만 있는 경로에 결재자 1명 또는 검토자와 마지막 결재자 순차 추가**, **빈 수신자 목록에 기관 1곳**, **빈 첨부 목록에 지정 파일 추가**다. 기존 데이터를 삭제하며 맞추지 않는다. 과제카드도 실제 이름과 대조한다. 과거 “특수교육교과활동” 요청의 실제 후보는 “특수교과교육활동”이었지만 이를 자동 치환하는 규칙으로 만들지 않는다. 개인 ID·기관 ID는 하드코딩하지 않는다.

결재 후보는 `draft-options --hwnd 실제값 --expected-title '현재 제목' --section approval`로 선택창을 열어 관찰한다. 이 명령은 사람을 추가하거나 확인하지 않는다. 열린 창을 다시 볼 때는 반환된 `--dialog-hwnd 실제값`을 지정한다. 기안자만 있는 선택창은 같은 옵션에 `--close`를 추가해 닫은 뒤 draft를 적용한다. `--section disclosure`는 현재 공개 구분과 사유 컨트롤을 조회한다. 후보는 전부 확인한 뒤 추가하며 중간 실패 시 열린 선택창을 보존하고 재실행하지 않는다.

과제 선택창은 `--section task`로 실제 배정 후보를 조회한다. 실패 후 이미 열린 창에는 같은 문서 제목과 `--dialog-hwnd`를 지정하고 `--task-card '후보의 정확한 표시명' --apply`로 남은 선택만 수행한다. 결재자 추가가 끝나고 확인 전 멈췄거나 회수한 기안의 기존 결재선 재확인이 필요하면 `--section approval --dialog-hwnd 실제값 --confirm-route 경로설정.json --apply`로 현재 선택된 모든 ID·이름·순서·역할이 설정과 일치할 때만 확인한다. 기존 경로가 있는 경우 주 화면의 현재 순번 행도 같은 경로여야 한다. 이 재개 명령은 사람을 추가하거나 기존 경로를 교체하지 않는다. 결재 표의 화면 정렬 순서가 아닌 실제 순번으로 경로를 대조하고 회수 전 이력 행을 현재 결재선에 합치지 않는다.

자동발송은 앱의 설정 확인 함수를 호출하며 실제 발송을 요청하지 않는다. 이 문서를 사용자가 나중에 결재올림하고 최종 결재가 완료되면 앱 정책에 따라 발송될 수 있다.

같은 임시저장 이름은 기본적으로 취소한다. 해당 초안을 교체하라는 사용자 지시가 있을 때만 `--replace-existing`을 붙인다. 네이티브 메시지는 정확한 이름의 교체 확인과 저장 성공 메시지만 처리한다. 다른 메시지는 열린 채로 둔다.

```powershell
python $wxsCli draft --config .\draft.json
python $wxsCli draft --config .\draft.json --hwnd 123456 --apply
python $wxsCli save-draft --name '테스트' --expected-title '테스트' --hwnd 123456 --apply
```

작업은 원자적 트랜잭션이 아니며 자동 롤백도 없다. 실패하면 입력 내용과 선택창이 남을 수 있다. `draft-status` 및 `completed_steps`를 보고 완료 항목을 뺀 설정으로 이어가며 `expected_title`도 현재 값으로 고친다. 저장 결과 불명은 임시보관함에서 확인한다.

첨부 계획에는 로컬 파일의 크기와 SHA-256이 포함된다. 입력 전과 각 첨부 직전에 원본을 다시 읽어 같은 크기로 바뀐 파일도 중단한다. 이는 로컬 원본의 변경 검사이며, 서버에 저장된 첨부 바이트를 검증했다는 뜻은 아니다. 임시저장 후에는 같은 초안을 재열람해 본문·필드·첨부를 대조한다.

## 표가 포함된 본문과 캡처 (0.4.0)

본문용 HWP는 나래 한글 오피스 CLI로 만들고 읽어 검토한다. 제목은 WXS의 title에 넣고 본문용 파일에는 안내 문장·표 등 본문 내용만 넣는다. body_hwp는 32 MiB 이하의 바이너리 HWP만 지원하며 HWPX 파일을 직접 넣지 않는다. 파일 해시와 빈 본문을 사전 확인한 뒤 표준 본문 필드로 이동해 HwpCtrl.SetTextFile(HWP, insertfile)로 끼운다. 이 끼우기 명령으로 기존 본문을 교체하지 않는다.

expected_text에는 안내 문장과 표의 모든 셀 원문을 행 순서대로 넣는다. 표 셀의 텍스트는 GetFieldText에 포함되지 않을 수 있으므로 전체 GetTextFile(TEXT)에서 삽입한 원문을 제외했을 때 이전 문서 전체와 같은지 확인한다. 공백·문단·셀 구분의 차이만 무시하며, 표준 필드 목록과 다른 필드의 값도 보존되어야 한다. 글꼴·테두리·배치의 정확성은 캡처로 별도 검수한다. 중간 실패 시 기존 내용에 반복 삽입하지 않는다. text와 capture로 실제 내용을 먼저 확인한다.

임시저장 성공 메시지를 확인한 뒤 실제 editor1의 모든 쪽을 이미지로 받을 수 있다. GUI 스크린샷이나 별도로 만든 미리보기 대신 선택한 WXS 한글 컨트롤의 페이지를 렌더링한다.

```powershell
python $wxsCli capture --hwnd 123456 --expected-title '현재 제목' --directory 'D:\검토\새캡처폴더' --dpi 150 --out 'D:\검토\캡처결과.json'
```

새 폴더만 허용하며 96~300 DPI, 최대 50쪽을 지원한다. CreatePageImage로 받은 BMP를 PNG로 저장하고 크기·SHA-256을 반환한다. 전후 제목·전체 문서 텍스트·본문 필드·수정 상태·쪽 수·결재경로·첨부가 같아야 verified:true다. 서버 저장 여부는 별도의 save-draft 성공 증거로 판단하며 캡처 자체는 저장이나 상신을 하지 않는다.

## 실제 글꼴 비교와 전체 기안 사본 적용

`insertfile`은 기존 양식의 스타일과 합쳐져 본문 파일과 다른 글꼴이 될 수 있다. 실제 문서를 `export-document`로 새 HWP 경로에 내보낸 뒤 나래 한글 오피스의 inspect로 글꼴·크기·문단·표를 읽는다. 전체 문서 텍스트와 메타데이터가 같은 경우에만 내보내기로 바뀐 편집 모드·수정 표시를 원래대로 복원한다. 이 명령은 열린 문서를 저장하거나 덮어쓰지 않는다. 초기 내보내기가 플래그 변경으로 실패했다면 `--restore-readonly-from`은 같은 제목·전체 TEXT 원문이 일치하는 읽기 전용 사본에 한해 복구한다.

편집할 때는 **현재 열린 편집 가능 기안의 전체 사본**을 먼저 내보내고 나래 한글 오피스로 필요한 본문 문단만 수정한다. 다른 문서나 참고 기안의 전체 파일로 대체하지 않는다. 실제 회수는 나래교무 브라우저의 문서진행에서 선택한 한 건의 제목·문서 ID와 확인창을 대조하고, 회수 상태를 다시 조회한 뒤 편집 기안을 연다.

```powershell
python $wxsCli export-document --hwnd 123456 --expected-title '현재 제목' --path 'D:\Codex\work\기안원본.hwp'
# 나래 한글 오피스로 사본 inspect → 본문 편집 → 수정 사본 inspect
python $wxsCli replace-document --hwnd 123456 --expected-title '현재 제목' --source 'D:\Codex\work\기안수정.hwp' --expected-text-file 'D:\Codex\work\수정전체원문.txt' --out 'D:\Codex\work\교체미리보기.json'
# 같은 인자에 --apply --expected-fingerprint '방금 검토한 지문'을 추가하여 적용
```

수정전체원문은 나래 한글 오피스로 읽은 제목·전체 본문·모든 표 셀·하단 필드를 순서대로 포함한다. 교체는 32 MiB 이하 HWP와 편집 가능·미처리 표준 기안에만 허용된다. 전체 HWP를 불러와 스타일 합치기를 피하며 표준 필드 목록, 본문 외 모든 필드, 결재선·과제카드·공개 설정·수신·첨부와 전체 원문을 대조한다. 실패 시 부분 변경 가능성을 보고하며 자동 재시도나 롤백을 하지 않는다. 성공 후 실제 WXS를 다시 내보내 나래 한글 오피스로 글꼴을 확인하고 capture로 배치를 검수한다. 임시저장·상신과 서버 완료 확인은 별도 절차다.
