# 기안 본문·붙임 작성과 줄 정렬

2026-10-30 사용자 교정을 반영한 이 포탈의 작성·검수 기준이다. 실제 양식과 사용자의 명시적 지시를 우선한다.

## 본문

- 제목은 업무 내용으로 쓴다. 임시 파일명이나 밑줄 등 장식 구분자를 옮기지 않는다.
- `1. 관련:`에는 실제 관련 기안의 정식 문서번호와 결재일을 확인해 쓴다. 추측하지 않는다.
- `2.`에는 보고·수립·운영 등 해당 기안의 목적과 조치를 쓰고, 필요한 세부 사항은 `  가.` 등 하위 항목으로 구분한다. 유사 기안의 실제 본문과 사용자의 요청을 대조한다.
- **항목이 두 줄 이상이면 둘째 줄부터 첫 줄의 내용 시작 위치에 맞춘다.** `2. 2026학년도 …`의 다음 줄은 `2.`의 왼쪽이 아니라 `2026학년도`의 왼쪽에 맞춘다. 긴 하위 항목과 붙임에도 적용한다.
- 내어쓰기·왼쪽 여백 설정을 우선한다. 직접 줄바꿈과 공백을 쓰더라도 실제 글꼴과 렌더링에서 시작 위치를 확인한다. `2. `의 폭을 확인하지 않고 임의의 고정 여백을 모든 문서에 적용하지 않는다.

## 붙임과 끝맺음

```text
붙임  1. 첫 번째 첨부 문서 1부.
      2. 두 번째 첨부 문서 1부.  끝.
```

- `붙임` 뒤에 쌍점을 넣지 않는다. 첫 번호와 다음 줄의 번호를 세로로 맞춘다.
- 실제 첨부와 문서명·순서·부수를 맞춘다. 본문에서는 확장자를 제외할 수 있다.
- 마지막 붙임 뒤에 한 글자 폭을 띄우고 `끝.`을 쓴다. 예시의 반각 공백 두 칸은 실제 글꼴에서 한글 한 글자 폭인지 확인한다.
- **본문 필드의 닫힘 표시 `』`는 `끝.`의 마침표 바로 오른쪽에 붙인다.** 마지막 공백·탭·줄바꿈·빈 문단 때문에 표시가 다음 줄 왼쪽으로 내려가면 미완성이다.
- `』`는 한글 필드 경계 표시다. 일반 문자를 입력해 흉내 내거나 필드를 삭제하지 않는다. 표준 `본문`·`결재제목` 필드를 보존한다.
- CLI의 `body`·`body_file`은 맨 뒤 공백과 줄바꿈을 제거한다. 내부 줄바꿈, 항목 앞 공백, 본문과 붙임 사이 빈 줄은 유지한다. HWP 본문·전체 기안 사본은 마지막 문단과 필드 경계를 따로 확인한다.

## 저장·상신 전 검수

1. 실제 WXS 사본을 나래 한글 오피스로 읽어 글꼴·크기·문단 서식을 확인한다.
2. `capture`로 실제 WXS의 모든 쪽을 보고 줄 넘김 정렬, 붙임 번호 정렬, `끝.` 바로 뒤 닫힘 표시를 확인한다. 추출 텍스트만으로 배치를 통과시키지 않는다.
3. 첨부·과제카드·보존기간·공개 사유·수신·결재자 순서가 요청과 같은지 확인한다.
4. 검수에 실패하면 수정 후 다시 확인한다. 상신 문서는 서버 회수 상태를 확인한 뒤 해당 편집 기안을 고치고 재상신 상태까지 검증한다.

실제 공문·학생 정보·개인 문서번호·세션 주소를 이 지침이나 공개 저장소에 기록하지 않는다.
