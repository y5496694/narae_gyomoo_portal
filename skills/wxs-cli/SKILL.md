# WXS (공문서 에디터) CLI

Windows의 같은 사용자 세션에서 이미 열린 WXS (공문서 에디터, WXS Client)를 MSHTML/HwpCtrl COM으로 처리한다. 현재 설치된 이 스킬의 `scripts/wxs_cli.py`를 실행한다. 과거 대화의 작업 폴더·hwnd·개인 ID를 재사용하지 않는다.

컴퓨터 유즈·마우스·키보드 자동화·OCR·클립보드를 사용하지 않는다. 기존 앱 함수·데이터셋·첨부 컨트롤과 확인된 Win32 대화상자 메시지로 처리한다. CLI가 지원하지 않는 단계는 설명하며 GUI 자동화로 전환하지 않는다.

## 조회

최초 실행은 [사용법](references/usage.md)을 읽고 `doctor`로 환경을 확인한다. `windows` 결과와 브라우저의 문서 제목·번호를 대조해 실제 hwnd를 선택한다. 여러 창 중 첫 창을 임의로 고르지 않는다.

```powershell
# $wxsSkill: 현재 설치된 이 SKILL.md가 있는 폴더의 절대 경로
$wxsCli = Join-Path $wxsSkill 'scripts\wxs_cli.py'
python $wxsCli doctor
python $wxsCli windows
python $wxsCli inspect --hwnd 123456
python $wxsCli text --hwnd 123456
python $wxsCli attachments --hwnd 123456
```

`123456`은 실제 반환값으로 치환한다. `text`의 추출 전후 편집 상태가 같아야 한다. 첨부 목록만 보고 파일 내용을 읽었다고 말하지 않는다. 그림·관인·문서 배치는 텍스트에 재현되지 않는다.

창이 없으면 웹에서 공문/양식을 여는 단계가 필요하다. 로그인·나이스/에듀파인 진입·검색은 별도 웹 도구의 범위다. 나이스가 열려 있다는 이유만으로 WXS CLI를 실행하지 않는다.

## 초안 입력

작성 요청을 받으면 [설정과 쓰기 범위](references/draft.md)를 읽는다. `draft-status`로 현재 값을 확인하고 사용자가 요청한 항목만 UTF-8 JSON 설정에 넣는다. `expected_title`은 현재 제목과 일치시킨다. 정확한 과제카드명·결재자·수신기관을 실제 후보와 대조한다.

`draft --config 설정경로`로 계획을 확인한 뒤 `--hwnd 실제값 --apply`로 실행한다. 작성·임시저장 요청은 해당 작업의 실행 허가이므로 같은 허가를 다시 묻지 않는다. 설명서 작성만 요청받은 경우 실제 문서를 변경하지 않는다.

표준 양식의 `본문`·`결재제목` 필드를 유지한다. 지원하는 추가 범위는 기안자만 있는 경로에 결재자 1명, 빈 수신자 목록에 기관 1곳, 빈 첨부 목록에 파일 추가, 대외 시행의 기본 관인 1개로 자동발송 설정이다. 기존 경로·수신자·첨부 교체와 다중 관인 선택은 지원하지 않는다.

저장 완료는 앱의 “정상적으로 처리되었습니다.” 메시지로 확인한다. 동일 이름 덮어쓰기는 해당 초안을 바꾸라는 사용자 지시가 있을 때만 `--replace-existing`으로 허용한다. 중간 실패 시 `completed_steps`·`attempted_step`과 현재 값을 대조해 남은 항목으로 이어간다. 전체 명령을 맹목적으로 재실행하지 않는다. 자동 롤백은 없다.

**결재올림·상신·승인·실제 발송 명령은 없다.** 자동발송은 결재 완료 후 발송을 예약하는 문서 속성만 설정한다. 사용자가 요청한 초안/임시저장까지 처리한다.

## 검증과 한계

[구조와 검증 기록](references/architecture.md)을 참조한다. 충북 WXS 3.0.0.2에서 조회와 개별 CLI 쓰기 절차를 실제 확인했다. 범용화한 이 배포본의 쓰기는 오프라인 모의 시험까지 확인했으며 전체 실제 저장과 다른 기관·버전은 추가 검증 대상이다. 세션 만료·양식 불일치·후보 중복·알 수 없는 창이면 멈추고 완료 지점과 원인을 보고한다.
