# 업무포털 공통 로그인·시스템 진입

## 교육청과 업무포털

### 자동화 전 최초 실행 3단계

새 PC 또는 새 브라우저 프로필에서 공문 자동화를 준비할 때는 아래 세 곳을 각각 최초 1회 실행한다. 사용자가 이 PC에서 확인한 초기 연동 절차이며, 표시되는 승인창은 사용자가 직접 처리한다.

| 순서 | 직접 실행할 곳 | 확인할 내용 |
| --- | --- | --- |
| 1 | 업무포털 | 로그인하고 표시되는 기기·로컬 앱 접근 승인을 완료한다. |
| 2 | K-에듀파인 | 업무포털에서 한 번 진입하고 표시되는 연동 승인을 완료한다. |
| 3 | 공문서 에디터(WXS) | 에듀파인에서 접근 가능한 실제 공문 한 건을 열고, 에디터 실행과 표시되는 초기 연동 승인을 완료한다. 목록만 조회한 상태로는 준비 완료가 아니다. |

이후 기존 로그인 세션과 열린 창을 확인해 자동화를 이어간다. 이미 승인된 단계는 다시 요구하지 않는다. 승인 대기나 에디터 실행 실패 시 진입 메뉴·공문 제목을 반복 클릭하지 말고, 현재 브라우저 안내와 원본 WXS CLI의 `windows`·`doctor` 결과를 확인한다. 첫 실행으로 이미 열린 공문은 새 창을 기다리는 `read-next`를 다시 시작하지 않고, 실제 제목·대상을 대조한 뒤 `read-open` 절차로 연결한다.

이 **초기 연동 승인**은 공문의 결재 승인·상신과 다르다. 나래 에이전트의 **‘모두 허용’** 설정도 브라우저·WXS의 초기 승인을 대신하지 않는다. 개별 보안문서가 요구하는 인증서 로그인은 별도이며, 인증 대기 창은 보존한다.

### 최초 실행 때 사용자가 직접 허용할 팝업

업무포털·나이스·에듀파인을 열 때 **‘이 기기의 다른 앱 및 서비스에 액세스’** 팝업이 나타날 수 있다. 최초 실행 시 이 허용은 **사용자가 직접 한 번 처리해야 한다**. 에이전트가 대신 허용하거나 컴퓨터 유즈·직접 API로 우회하지 않는다. 팝업 때문에 진행이 막힌 해당 단계에서 사용자에게 허용을 안내하고, 허용 뒤 현재 화면과 연결 상태를 다시 확인해 이어간다. 이미 허용된 상태라면 같은 확인을 반복 요구하지 않는다. 새로운 브라우저·프로필 등에서 다시 나타난 경우 그 팝업은 다시 사용자에게 맡긴다.

### 기본 접속 대상

공개 접속 설정은 [portal.json](portal.json)에 있다. 기본 지역은 **충북**, 기본 주소는 [충북 업무포털](https://cbe.eduptl.kr/bpm_lgn_lg00_001.do)이다.

나이스·에듀파인은 업무포털을 거쳐 들어간다. 두 시스템의 직접 주소를 추측하거나 다른 도의 주소로 대체하지 않는다.

사용자가 충북 이외의 지역을 말하면 다음처럼 안내한다.

> 이 스킬은 충북 업무포털 주소를 기본으로 사용합니다. 다른 지역에서는 해당 교육청의 업무포털 주소로 스킬의 `references/portal.json`을 갱신해야 합니다.

그 지역의 확인된 업무포털 주소로 `region`과 `portal_url`을 함께 갱신한다. 사용자가 주소를 제공하지 않았고 확인 가능한 공식 주소도 없다면 주소를 확인할 때까지 로그인을 진행하지 않는다. 개인 보안 문서의 `region`과 스킬의 지역이 다르면 설정 불일치를 먼저 해결한다. 지역·개인 설정이 없을 때만 필요한 정보를 묻고, 실제 인증서 암호를 채팅에 요청하지 않는다.

## 개인 인증서 보안 문서

로그인 전 [local-certificate.md](local-certificate.md)를 읽는다. 개인별 문서에서 다음 정보를 가져온다.

| 항목 | 용도 |
| --- | --- |
| 지역 | 업무포털 설정과 일치 여부 확인 |
| 저장매체 | 하드디스크 / 이동식 디스크 구분 |
| 인증서 경로 | 해당 PC의 실제 인증서 위치 확인 |
| 인증서 이름 | 인증서 목록에서 본인의 인증서 식별 |
| 저장소 이름(필요 시) | 저장소 후보가 여러 개일 때 대조 |
| 이동식 디스크 식별 | USB 사용 시 드라이브·볼륨 이름으로 대상 구분 |
| 인증서 암호 | 인증서 암호 입력란에만 전달 |

기존 보안 로컬 문서가 지정되어 있으면 그 문서를 사용한다. 새 등록이 필요하면 제공된 로컬 등록 도우미를 사용한다. 배포 스킬과 에이두 옵시디언에는 실제 개인 인증서 경로·이름·암호를 복사하지 않는다. 인증서 파일 자체도 수집하거나 업로드하지 않는다. 개인 보안 문서의 평문 전체와 암호를 도구 출력·로그·스크린샷·클립보드에 남기지 않고, 로컬 메모리에서 암호 입력 API로 전달한다.

문서가 없거나 필수 항목이 비어 있으면 등록 방법을 안내하고 해당 단계에서 멈춘다. 인증서 위치를 PC 전체에서 무작정 검색하거나 USB 첫 항목·인증서 첫 행을 임의로 선택하지 않는다.

## 업무포털 로그인

**사용자의 직접 로그인을 우선한다.** 유효한 세션이 없으면 업무포털을 열어 두고, 가능하면 사용자가 브라우저에서 직접 로그인한 뒤 알려 달라고 안내한다. 직접 로그인에는 인증서 암호를 읽어 올 필요가 없다.

사용자가 자동 로그인을 요청한 경우에만 개인 보안 문서 절차를 사용한다. 시작 전에 다음 내용을 안내한다.

> 브라우저 컨트롤을 통한 인증서 로그인은 서버 쪽에서 차단될 수 있습니다. 자동 로그인은 1회만 시도하고, 실패하거나 결과가 불명확하면 직접 로그인으로 이어가겠습니다.

이 경고는 차단 가능성에 대한 안내이며, 오류가 자동화 차단 때문이라고 확정하는 진단이 아니다. SSO 1005 등 오류, 인증서 제출 후 시간 초과, 로그인 결과 불명확 상황에서 인증서 제출을 반복하지 않는다. 새로고침·주소 변경·도구 전환으로 자동 시도 횟수를 초기화하지 않는다. 오류와 완료 지점을 알리고 사용자 직접 로그인 후 실제 화면을 확인한다.

**WXS의 별도 인증서 창을 곧바로 세션 만료로 판단하지 않는다.** 보안문서 열람에도 인증서 암호를 요구할 수 있다. 그 문서는 사용자에게 보안문서의 추가 인증이 필요하다고 알리고 **WXS와 인증창을 닫거나 지우지 않은 채** 인증 대기로 남겨 다른 문서를 계속 확인한다. 암호를 자동 입력하지 않는다. 실제 포털 세션 만료가 확인되면 사용자 직접 로그인을 요청한다. 보안문서 인증과 세션 재로그인을 혼동해 모든 WXS 창을 닫지 않는다.

## 장시간 작업 중 세션 유지

활성 업무를 진행하는 동안 **30분마다 두 시스템의 연장을 각각 수행**한다. 두 시스템의 기본 유효시간은 **60분**이며 버튼을 누르면 다시60분부터 시작한다. ‘30분마다’는 작업 중 실행 주기이며 기존 잔여시간에30분을 더한다는 뜻이 아니다.

- 업무포털 상단 시간 옆의 새로고침 아이콘: 접근성 이름 **세션 시간 초기화**. 문서함 포틀릿의 `새로고침`과 구분한다.
- K-에듀파인 왼쪽 상단의 **연장**: 접근성 이름 **로그아웃 30분 연장**.

사용자가 보고 있는 업무포털·에듀파인 **기존 탭 ID를 기록하고 같은 탭에서** 누른다. 버튼 실행 후 실제 화면의 시간 숫자가 `60:00` 또는 경과한 만큼의 `59:xx`로 바뀌었는지 확인하고 탭 ID·성공 시각·표시값을 기록한다. 에듀파인의 접근성 설명만60분으로 바뀌고 텍스트·화면 그리기가 늦게 따라올 수 있으므로 설명 문자열만으로 완료를 판정하지 않는다. DOM의 실제 표시 텍스트와 새 화면으로 대조한다.

기존 탭 제어가 끊겨 별도 탭을 복구했다면 **복구 탭의 성공과 기존 탭의 실패를 구분해 보고**한다. 다른 탭의 표시·세션까지 함께 갱신됐다고 단정하지 않는다. 기존 탭의 버튼을 실행할 수 없으면 그 한계를 알리고 사용자가 그 탭에서 직접 버튼을 누르도록 안내한다. 기존 화면을 그대로 두고 새 탭만 반복 생성하는 방식으로 기존 탭 연장을 완료했다고 말하지 않는다.

오래 걸리는 작업을 시작하기 전에30분을 넘길 상황이면 먼저 연장한다. 브라우저 전체 새로고침으로 작성 중인 내용을 잃지 않도록 실제 세션 연장 버튼을 사용한다. 이 절차는 현재 작업 중의 세션 유지이며 상주 자동화나 예약 작업을 새로 만들라는 뜻이 아니다.

## 허가된 자동 로그인 절차

아래는 허가된 **자동 로그인 1회**의 절차다.

1. 사용자가 지정한 브라우저 또는 해당 업무포털이 이미 열린 브라우저를 사용한다. 최신 상태를 확인하고, 이미 요청 대상 시스템에 로그인되어 있으면 현재 세션을 재사용한다. 유효한 세션에 인증서 암호를 다시 입력하지 않는다.
2. 설정의 업무포털을 열고 현재 주소와 로그인 화면을 확인한다. 충북에서 확인한 버튼명은 **교육행정 전자서명 인증서 로그인**이다. 화면이 바뀌면 현재 보이는 로그인 요소로 판단한다.
3. 인증서 로그인 버튼을 누르고 새 상태를 확인한다. 창이 나타나지 않으면 브라우저의 안내·팝업·설치 요구를 확인한다. 같은 버튼을 반복해서 누르거나 자동 설치·보안 설정 해제로 해결하지 않는다.
4. 보안 로컬 문서의 저장매체에 따라 아래 순서로 진행한다. 각 목록에서 개인 설정과 실제 항목을 대조한 뒤 선택한다.

| 저장매체 | 선택 순서 |
| --- | --- |
| 하드디스크 | **하드디스크 → 저장소 → 등록된 인증서 선택 → 아래 인증서 암호 입력 → 하단 확인** |
| 이동식 디스크(USB 등) | **이동식 디스크 → 나온 목록에서 등록된 이동식 디스크 선택 → 저장소 → 등록된 인증서 선택 → 아래 인증서 암호 입력 → 하단 확인** |

5. 인증서 경로는 저장매체·저장소를 맞추는 단서로 사용한다. 실제 화면에 경로 입력·가져오기 기능이 있을 때만 그 기능에 경로를 입력한다. 보이지 않는 입력란을 만들어 내지 않는다. USB 드라이브 문자가 바뀌었다면 등록된 볼륨 이름과 경로를 대조한다. 디스크 또는 인증서 후보가 여러 개이고 구분되지 않으면 확인을 요청한다.
6. 암호 입력 직전에 주소와 인증서 선택을 확인하고 로컬에서 불러온 암호를 입력한 뒤 **확인**을 한 번 누른다. 암호 오류가 나오면 자동으로 같은 암호를 재입력하지 않는다. 오류와 필요한 설정 수정을 알려 주되 암호는 표시하지 않는다.
7. 아래 시스템 목록과 로그인된 업무포털 화면을 확인한다. 클릭만으로 로그인 완료라고 보고하지 않는다. 추가 인증을 도구로 처리할 수 없으면 해당 단계만 사용자에게 넘긴다.

## 나이스·K-에듀파인 진입

로그인 뒤 업무포털에서 다음 항목을 찾는다. 표시 순서에 의존하지 않는다.

- **나이스**
- **K-에듀파인**
- **기록관리시스템**
- **교육행정데이터통합관리**

나이스 요청은 **나이스**, 에듀파인 요청은 **K-에듀파인**을 누른다. 두 시스템을 모두 요청하면 각각의 진입을 확인한다. 대상이 정해지지 않은 로그인 요청은 업무포털 로그인 완료에서 멈춘다. 기록관리시스템과 교육행정데이터통합관리는 식별 단서이며 이번 지원 대상이 아니다.

클릭 후 브라우저의 열린 탭 목록을 확인하고 같은 탭 또는 새 탭에 열린 실제 대상 시스템의 제목·현재 화면을 대조한다. 새 창이 없으면 차단 안내와 브라우저 상태를 확인한다. 추가 인증서 로그인이 나타나면 사용자 직접 인증을 우선한다. 이미 사용한 자동 로그인 시도 횟수를 시스템 진입을 이유로 초기화하지 않는다. WXS 보안문서라면 위의 보존·인증 대기 절차를 적용한다.

요청한 시스템의 실제 화면을 확인했을 때만 “나이스에 진입했습니다” 또는 “K-에듀파인에 진입했습니다”라고 보고한다. 업무포털만 로그인됐거나 시스템 열기가 실패했으면 완료한 지점과 원인을 구분한다. 인증서 정보·암호는 결과 보고에 넣지 않는다.
